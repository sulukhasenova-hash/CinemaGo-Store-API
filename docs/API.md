# Контракт CinemaGo Data API

Базовый адрес: `http://127.0.0.1:8081/v1/`

Все маршруты, кроме отсутствующих ресурсов, требуют заголовок:
`Authorization: Bearer <API_TOKEN>`

Успех: `{"ok":true,"data":...}`. Ошибка:
`{"ok":false,"error":{"code":"...","message":"..."}}`.

| Метод и путь | Параметры | Назначение |
|---|---|---|
| GET `/health.php` | — | Проверка API и SQLite |
| POST `/auth.php` | JSON: `login`, `password` | Проверка пароля и безопасный профиль |
| GET `/products.php` | необязательный `id` | Каталог, цены, остатки, категория |
| GET `/categories.php` | — | 8 категорий и 24 подкатегории |
| GET `/users.php` | `user_id` | Безопасный профиль и группа |
| GET `/preferences.php` | `user_id` | Матрица пользователь × предпочтение |
| GET `/groups.php` | — | Группы, группа × предпочтение, группа × категория |
| GET `/product-matrices.php` | — | Товар × предпочтение и товар × товар |
| GET `/events.php` | `user_id` | История действий |
| POST `/events.php` | JSON: `event_id`, `user_id`, `product_id`, `event_type`, `preference_changes` | Сохранение события и коэффициентов в одной транзакции |

## Пример запроса
```bash
curl -H "Authorization: Bearer YOUR_TOKEN" http://127.0.0.1:8081/v1/products.php
```

## Пример POST события
```json
{
  "event_id": "evt-unique-000001",
  "user_id": 1,
  "product_id": 12,
  "event_type": "cart",
  "preference_changes": {"1": 0.4, "2": -0.2}
}
```

## HTTP-статусы

- `200` — успешное чтение/операция.
- `201` — новое событие создано.
- `400` — некорректный JSON или параметры.
- `401` — отсутствует/неверен служебный токен либо неверные данные входа.
- `404` — объект не найден.
- `405` — неверный HTTP-метод.
- `500` — внутренняя ошибка.
- `503` — сервис или база недоступны.

## Таблицы и матрицы

| Матрица | Таблица |
|---|---|
| пользователь × предпочтение | `user_preferences` |
| группа × предпочтение | `group_preferences` |
| группа × категория | `group_categories` |
| товар × предпочтение | `product_preferences` |
| товар × товар | `product_similarity` |

SQLite используется только API. Магазин получает данные через cURL/HTTP и не содержит PDO/SQL. Балл рекомендации вычисляется на стороне магазина: индивидуальные веса × признаки товара + вклад группы + категория + небольшой сигнал истории. При равных баллах сортировка стабильна по ID товара.
