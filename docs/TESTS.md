# Ручные проверки (шаблон отчёта)

Заполните колонку «Фактический результат» после выполнения и добавьте собственные скриншоты. Не отмечайте тест как пройденный, пока не выполнили его самостоятельно.

| № | Проверка и действия | Ожидаемый результат | Фактический результат |
|---|---|---|---|
| 1 | Остановить Apache, оставить API и запросить health/products с токеном | API отвечает 200 и JSON независимо от магазина | Заполнить после проверки |
| 2 | Запросить preferences для двух аккаунтов, groups и product-matrices | Получены все пять матриц; данные аккаунтов различаются | Заполнить после проверки |
| 3 | Запросить несуществующий ID, неверный параметр, неправильный метод и испорченный JSON | Соответствующие JSON-ошибки и статусы 404/400/405/400 | Заполнить после проверки |
| 4 | Сравнить рекомендации для user1, user2 и гостя | Персональные списки различаются, каталог единый | Заполнить после проверки |
| 5 | Изменить коэффициент в SQLite и повторно запросить preferences | API возвращает новое значение, магазин пересчитывает баллы | Заполнить после проверки |
| 6 | Выполнить действие в магазине, затем запросить events/preferences | Событие и предпочтения сохранены | Заполнить после проверки |
| 7 | Остановить API при работающем Apache | Магазин показывает ошибку, не читает SQLite напрямую | Заполнить после проверки |
| 8 | Отправить запрос без токена и проверить доступ к чужому профилю | API отвечает 401; магазин использует ID из сессии | Заполнить после проверки |
| 9 | Повторить POST с тем же event_id и отправить неверный коэффициент | Повтор не дублируется; неверная транзакция откатывается | Заполнить после проверки |
| 10 | Поискать в папке shop `PDO`, `sqlite:`, `SELECT`, `INSERT`, `UPDATE`, `DELETE` | Прямого доступа к БД в магазине нет | Заполнить после проверки |
| 11 | Перезапустить API и Apache, повторно запросить события и preferences | Данные сохраняются после перезапуска | Заполнить после проверки |

## Git

Рекомендуемые коммиты в отдельной ветке `feature/data-api`:
1. `Create separate PHP data API`
2. `Add SQLite schema and seed data`
3. `Implement API routes and matrices`
4. `Connect PHP shop through HTTP client`
5. `Add recommendation ranking and event transactions`
6. `Document API and manual tests`

Создайте Pull Request на GitHub и приложите скриншоты реальных проверок.
